テスト用DBを初期化しました

[単体] 入力の検証
  ok   正しい施設は整形されて通る（緯度経度は小数6桁）
  ok   不正な入力はすべて弾く（空の名前・範囲外・文字・未知のカテゴリ・長すぎる）
  ok   ホテル設定の検証（ズーム・カテゴリ・中心）

[単体] DB（SQL の特殊文字・カテゴリ表示）
  ok   SQL の特殊文字を含む名前が、そのまま保存・取得でき、テーブルは壊れない
  ok   ホテルのスラッグに SQL を入れても、全件は返らない
  ok   地図に出すのは、そのホテルで有効なカテゴリの施設だけ（札幌は「交通」が無効）
  ok   パスワードは平文でなくハッシュで保存され、照合できる

[単体] 取り込み（冪等・不正な行のスキップ）
  ok   1回目: 有効な10件を追加し、不正な7件はスキップする
  ok   スキップの理由が DB とログファイルに残る
  ok   2回目（同じデータ）: 件数が増えない（冪等）
  ok   内容が変わった行だけ更新される（追加はされない）
  ok   壊れたファイルは、何も変えずにエラーにする

[HTTP] 認証・CSRF・SQL・XSS（実際にリクエストを送る）
  ok   未ログインで管理画面を開くと、ログイン画面へ飛ばされる
  ok   未ログインの POST（削除・追加）は、何も変えない
  ok   ログイン: CSRF なし・間違ったトークンは 403、間違ったパスワードは拒否
  ok   ログイン成功でセッションIDが変わる（固定化攻撃への対策）／クッキーは HttpOnly・SameSite
  ok   施設の追加: CSRF なし・違うトークンは 403で件数不変、正しいトークンで追加される
  ok   管理画面の入力に SQL の特殊文字を入れても壊れず、API がそのまま返す
  ok   XSS: 管理画面は施設名の HTML をエスケープして出す
  ok   不正な入力（緯度999）は 200 でエラーを表示し、DB は変わらない
  ok   施設の削除: POST＋CSRF のときだけ。GET では消えない
  ok   ホテル設定: 正しい値は反映され、不正な値は拒否される（地図の中心・ズーム・カテゴリ）
  ok   ログアウトは POST＋CSRF のときだけ。その後は管理画面に入れない

[HTTP] 地図の API と画面
  ok   API の件数 = 画面に出す施設の数（DB で数えた表示対象の件数）。3ホテルすべて
  ok   カテゴリで絞り込める。無効なカテゴリ・空の選択は0件
  ok   API の異常系: 存在しないホテルは404、不正なスラッグは400（SQL 文字を含む）、POST は405
  ok   地図ページ: ホテル名と Leaflet を含み、キーが未設定なら Google のキーを出さない
  ok   管理画面: 取り込み履歴の日時は日本時間で表示（DB は UTC）
  ok   管理画面: 「地図に表示」の列は「表示／非表示」の文言（札幌は交通が非表示）

結果: 29 件合格 / 0 件失敗
